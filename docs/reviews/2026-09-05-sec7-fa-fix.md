# Section 7's Plane A factors — corrected through the UI, and the sentence the panel owed

**Branch** `parcel/sec7-fa-fix` · **2026-09-05**

The owner, off the running game: *"only thing I see in section 7 is the fg loading wrong?"*

`ojz_act1_sec7_worldwater` — authored in Aurora, landed in aeon at `c1d0a6be` — set the
**plane A** scroll factor below `FACTOR_1` on two of its three layers. Plane A is the plane
the player physically stands on, so a factor other than `FACTOR_1` makes the picture and the
collision disagree: the foreground slides under his feet. The picker offered those values,
took them, and said nothing.

Two halves: the scene is corrected **through the real UI**, and the panel now says why the
value was wrong.

### The census, taken rather than asserted

The tempting sentence is "every shipped scene uses `FACTOR_1`". It is a number, so it was
**derived**, at the same revision, over every scene aeon ships:

| scene | layers | `fa` values |
|---|---|---|
| `ojz_act1_start.json` | 5 | `FACTOR_1` ×5 |
| `ojz_act1_depth.json` | 5 | `FACTOR_1` ×5 |
| `ojz_act1_floor.json` | 3 | `FACTOR_1` ×3 |
| **13 layers across 3 scenes** | | **13/13 `FACTOR_1`** |
| `ojz_act1_sec7_worldwater.json` | 3 | `FACTOR_1_8`, `FACTOR_1`, `FACTOR_3_4` — **the only exception** |

(`ojz_act1_depth` is a fourth shipped scene the dispatch's table did not name; it is included
above and it agrees.) `fb` varies freely across all four — 5 distinct values — which is the
point: **`fb` is the parallax dial, `fa` is not.**

This count is deliberately **not** in the app's advisory string. A census needs the revision it
was taken at to mean anything, and a string in the app cannot carry one — it would rot silently.
It lives here.

### Why the advisory ADVISES and does not refuse — derived, not assumed

`parseColours`' docblock (`src/renderer/providers/effects-preset.ts`) and `boundary.ts`'s header
carry the ruling: *a control that refuses what the generator accepts **looks like diligence** and
is a bound we invented.*

That aeon accepts a non-`FACTOR_1` `fa` was **checked in the engine**, not taken on trust:
`layer()` in `scene_dsl.emp` carries **twelve `ensure`s** and **not one of them mentions `fa`**.
They cover `world_y`; the `own()`/`deform` pairing; `dsa`/`dsb`/`phase` under `own()`; the own
shifts, phase and speed bounds; and the five curve rules (`curve` vs deform amplitude, `curve`
vs `own`, `curve_to` range, `curve_to != fb`, `curve` vs `enabled`). A document carrying any
`fa` builds. So Aurora says it and does not block it: the picker keeps every option, and the
scene still saves.

**Packed factors say nothing.** `{s1,s2,op}` is the escape hatch and a packed triple can encode
1:1; deciding that from the panel needs the engine's decoder, and guessing would put a false
sentence in front of an author who did the harder thing correctly. `isNamedFactor` is the gate —
the same split `curveFieldOptions` keeps, for the same reason.

### One rig fault found and fixed, worth writing down

The first `npm test` here died in `check-cited-paths` with *"the exit-0 arm is not behaving …
got []"* — a refusal that reads exactly like a broken gate. It was **mine**: this worktree had
no `node_modules`, so it was given one as a **symlink** to the main checkout's, and
`git check-ignore` will not answer for a path that traverses a symbolic link — so the probe's
`node_modules/__check-cited-paths-ignore-probe__` came back unjudged. Replacing the symlink with
a real directory of per-entry symlinks fixed it; the gate then passed and, incidentally,
validated this parcel's own comment citations. **It is not a defect in the gate, and it was not
on master.** Anyone rigging a worktree by symlinking `node_modules` will hit it.
