## 3. P2, in full, because it is the one that changes something

### 3.1 The result

The seat's walk, replayed verbatim on the fixed build with the seat's own numbers (`Top` 112,
`Bot` 128): click `Top`, type `40`, **Tab**, **click** `Bot`, type `72`.

```
Bot's box after ONE keystroke : "1287"        <- the caret INSERTED
Bot's box after both          : "12872"       <- seat A's exact value
the document                  : bot = 128     <- correctly refused, never written
```

**One keystroke is the discriminator**, deliberately. `NumberField` commits per keystroke, so a
two-key read has to be untangled from the per-keystroke refusal arithmetic; a single `7` cannot.
`"7"` means the selection was replaced. `"1287"` means the caret was placed and the digit inserted.

### 3.2 The census — and why it exists at all

**The first version of this row ran exactly the two arms the finding asks for, and BOTH inserted.**
That would have read as *"the app inserts on every click"*, which contradicts the committed
`scratchpad/effects-refusal-harness.mjs`, whose floor row `[5a]` types a legal value after a blurred
click and watches the model take it. **That harness was run on this same tree and `[5a]` passes.**

A control that fails where an independent instrument passes is a **broken control**, and a broken
control manufactures a false refutation that looks exactly like the rule failing. So the variable
was **enumerated instead of assumed** — seven gestures, one run, one box each, same layout:

| | gesture | focused at click | after 1 key | verdict |
|---|---|---|---|---|
| **A** | `Top` → **Tab** → click `Bot` → type — *the seat's walk* | **true** | `1287` | **INSERTED** |
| **B** | A, plus one `blur()` before the click | false | `1287` | **INSERTED** |
| **C** | B with no gap between keystrokes | false | `1287` | **INSERTED** |
| **F** | B with a 2s settle before the click | false | `1287` | **INSERTED** |
| **G** | `Bot` clicked, blurred, then clicked **again** (no Tab) | false | `1287` | **INSERTED** |
| **D** | cold click on `Bot`, no Tab | false | `7` | **REPLACED** |
| **E** | cold click on `Top` — `[5a]`'s own conditions | false | `7` | **REPLACED** |

**Reproduced identically in three runs** at loads 7.8, 10.5 and 11.8.

### 3.3 What this rules out, and what it does not

`D` and `E` are the **anti-vacuous floor**: a cold click still replaces, in the same run, so the
split is a property of the gesture and not of a dead app. `E` reproduces the committed harness's own
conditions inside this run, so the census carries its cross-check rather than citing another run's
green.

**Ruled out as the mechanism:**

* **"a click on an ALREADY-FOCUSED box"** — the finding's own words. `B`, `C`, `F` and `G` were
  provably **unfocused** at the click and inserted anyway.
* **the Tab** — `G` uses no Tab at all and inserts.
* **the inter-keystroke gap** — `B` and `C` differ only in that and agree.
* **a React flush race** — `F` waits a full 2 seconds after the blur and still inserts.

**NOT ruled in.** ⚠ **The census does not isolate the surviving variable, and this packet does not
guess at one.** The nearest empirical statement the seven rows support is *a box that was focused
immediately before, with nothing typed into it in between, does not re-select when clicked* — `D`
and `E` are the two whose targets were last left after a **committed edit**. That is a correlation
over seven points, not a mechanism, and it is written here as a lead for whoever fixes it rather
than as a diagnosis. **The reproduction recipe is exact and is in the harness.**

### 3.4 What follows for the two findings

* `FIELD-GROUP-REFLOW-F4` — **stays closed.** P1 confirms it on the geometry, and a panel growing
  under a reader's hand was a real defect on its own terms.
* `NUMBERFIELD-FOCUSED-CLICK-INSERT` — **stays open**, upgraded from *derived-from-source* to
  **reproduced**, with its stated mechanism **corrected**. Updated in `docs/lens-findings.jsonl`
  under its own id.

## 4. P3 — the premise is a height, and it belongs to another surface

P3 asks for the refusal *"at a squeezed column width (this panel's scroller has measured 129px)"*.
**That 129px is not a width and not this scroller.** It is traceable to two of this repo's own
documents:

* `docs/reviews/2026-09-02-effects-sub-tabs.md` — its table measures the **Parallax** sub-tab's
  **LAYERS LIST** at *"129px onto 2,460px"*, a scroller **body height** standing on
  `SECTION_LIST_MIN_HEIGHT`.
* `docs/reviews/2026-09-02-effects-drift-control.md` §238 — *"THE LAYERS LIST IS 129px TALL"*.

The Colour column this refusal renders in is **fixed at 300px wide** (`column-layout.tsx:77`:
*"THE COLUMN IS 300px AND EVERY PIXEL IS ZERO-SUM"*). Narrowing the window to 900px **did not move
it**: measured 300px before and 300px after.

**So the condition as written cannot be produced, and no verdict on it is offered.** What was
measured instead is the row at the width the app actually has:

* **PASS** — painted, inside its own scroller's box, hit-testable at its centre, not clipped
  horizontally, not overflowing right.
* **PASS** — it carries its **whole** sentence, rule and all: *"...a fire must land on 3..223 (lines
  0-2 belong to the priming records). Refused; Bot is still 128."*

Forcing the scroller to 129px anyway is **recorded and explicitly not a verdict**: the label column
consumes the row, the sentence wraps to roughly one character per line (19px wide, 1,155px tall) and
leaves the scroller's box entirely. **That is not a state the app can be in**, so it says nothing
about the shipped app.

## 5. The three UNMEASURABLE rows, each with its actual reason

**These are limits of this instrument's reach. None of them is evidence about the app**, and none is
reported as a failure.

### S2 — `Ctrl+S` flashing `Saved!`

The chip itself is **confirmed** (S1: painted, hit-testable, tooltip `Nothing to save in this
document`). What could not be reached is a **dirty level document**. Four routes were tried:

| route | what happened |
|---|---|
| an Effects-preset edit | writes a **different document** — `aeon.state().dirty` is the editor store's *level* flag |
| `__dbg.setFacet("layout")` | returns `null` |
| the `Layout` pill found as a `div` | not found — it is a `BUTTON` |
| the `Layout` pill found across tags | **clicks**, but the `t` tool letter leaves `tool` at `view` |

The classic viewport is `ClassicLevelViewport`, whose key handling is not `MapViewport`'s, and arming
its paint tool from outside is a door this harness does not have. Saying **UNMEASURABLE** is the
honest verdict; saying FAIL would put a defect on the app that this run has no evidence for.

### S3 — the classic save toast naming files

Blocked behind the same gesture. The classic half **did** reach further than any prior run: the
copied `s1disasm` opened (18 zones), and **Green Hill Zone Act 1 loaded** (`levelState
{"status":"ready","zone":"ghz","act":1}`) with a `Save` control on its header. With nothing dirty, no
`Saved N level(s)` toast is due, so there was no sentence to inspect.

⚠ **One near-miss worth recording.** The first version of this row asked for `status === 'open'` and
read the **loaded** act as *"no act could be opened"* — a predicate **one word** off its store's own
vocabulary, reported as a fact about the project. It is fixed and the store's words are what is
asked for now.

## 6. The rows that passed, with the number that makes each non-vacuous

* **P1** — `Bot`'s y `492.91 → 492.91` while a `Top` refusal paints; `Top`'s y `436.91 → 436.91`
  while a `Bot` refusal paints. The refusal is asserted **painted** in the same read, so an
  unchanged y over an unchanged page cannot pass. `S/H` still moves (`520.91 → 739.41`) — that is
  §2.4's **named residual**, not a failure of this row.
* **P4** — **0 gestures**, against the seat's 4. Measured with **the seat's own deltas** (600, 600,
  700, 700) rather than a delta this sweep invented, because a count in a different unit reads as
  the same number. `Preset id` is `inView` at `scrollTop: 0`, and the row separately asserts the
  input is **mounted on arrival**, so "0" is a depth measurement and not a measurement of its
  absence.
* **P5** — the timeline canvas is 258×280, painted, **below** the preset panel in document order,
  and **2,048 non-transparent pixels** were sampled from its own bitmap. Source can prove the
  absence of `defaultCollapsed`; only a screen proves the canvas is there.
* **P6** — explorer width **240px**. The affordance is a `BUTTON`, has **no placeholder**, and is
  **not on `Filter…`'s row** (57px above it). The `Filter…` box is the **positive control** and was
  found in the same read — without it, "they are not side by side" could be a broken query's
  confident zero. Its label reads `Run a command` with `Ctrl+K` beside it and the full tooltip
  `Run a command (Ctrl+K or Ctrl+Shift+P)`.
* **P7** — a real `Input.dispatchKeyEvent` with Ctrl+Shift, never a synthetic `dispatchEvent` the
  app would be free to ignore. The palette's own input appears, **painted and focused** — not opened
  underneath something, which is the failure its own source comment records.
* **S1** — the chip is painted at the end of the level header and hit-tests to itself.
* **way-in 1** — the field is on the cold Home hero page, placeholder `/home/you/s1disasm`, below
  `Open Project…` (field top 221 vs button top 128).
* **way-in 2** — the real path is **typed** into the box (asserted before Enter), and Enter opens the

  *"Your shell expands ~, not Aurora, so a pasted ~ is a directory named "~". Type the full path

⚠ **way-in 4 also cost a false negative worth recording.** Its first version clicked the Home tab

a real press/release at an integer point, and the loop stops only when the Home pane is actually on
screen.

⚠ **`check:cited-paths` and the `node_modules` symlink.** A linked worktree has no
`node_modules/`, so one was symlinked in to get a toolchain. `git check-ignore` then refuses every
path under it — *"pathspec ... is beyond a symbolic link"*, exit 128 — so the gate's own exit-0
self-test probe comes back empty and it reports **COULD NOT MEASURE** rather than going green. That

symlinks `node_modules`**, and it says nothing about this parcel's files.

harness-like file that no `package.json` script can reach is one nobody can run by name, so nothing
sweeps it and a red row inside it is invisible. All three are now registered:
`harness:cdp-sweep-f4`, `harness:cdp-sweep-panels`, `harness:cdp-sweep-wayin`.
