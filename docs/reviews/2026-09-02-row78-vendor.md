## The split, and why it is not a preference

Phase 1 measured the class-A dependency set at 656 files / 2.18 MB, of which
`_incObj` is 136 files / 1.35 MB read by **one file for two rows**. Those two
rows are the whole reason this is a split and not a bulk copy:

| question a row asks | the honest instrument | why the other one is wrong |
|---|---|---|
| *Does OUR code handle this document?* | a **PIN** — bytes committed here | the input must not move, or the row measures two things at once and a peer's art edit reads as our regression |
| *Has the peer's SOURCE moved?* | a **COMMITTED PEER REVISION** | a pin equals itself by construction; the row would pass forever |

`s1-sync-anims.test.ts:183`, `'no fifth consumer hides in _incObj (the table is
complete)'`, is the second kind. Vendoring `_incObj` would have made it green
forever — a vacuous gate in its most convincing costume, because everything
about it would still *look* rigorous.

**This is not an argument, it is a measurement.** Against a clone of the peer
with a fifth consumer committed at its tip:

```
the disassembly moved: pin f6ece657… -> tip 263e9a86…

ASKED OF THE TIP (what the currency row does) — 4 file(s):
    _incObj/17 GHZ Spiked Pole Helix.asm
    _incObj/25, 37 Rings.asm
    _incObj/4B, 7C Giant Ring and Flash.asm
    _incObj/99 Fifth Consumer.asm

ASKED OF THE PIN (what a vendored _incObj could ever see) — 3 file(s):
    _incObj/17 GHZ Spiked Pole Helix.asm
    _incObj/25, 37 Rings.asm
    _incObj/4B, 7C Giant Ring and Flash.asm
```

The pin answers 3 and is green, because it is a copy of a tree that held 3 — and
it would be green for every future fifth consumer too.

## THE CURRENCY CHECKS

**`src/core/project/profiles/__tests__/s1-sync-anims.test.ts`** — three rows,
now `S1 sync animation table — CURRENCY cross-check (s1disasm at a committed
revision)`. They read `../s1disasm` at **`origin/AS`** through git objects
(`readAtRev`, and a new `grepAtRev` in `test/support/peer-repo.ts`), name that
revision in their own titles and in every message, FAIL on drift prefixed
**NOT AN AURORA REGRESSION**, compare CONTENT not commit ids, print the artifact
they judge, and skip with `ctx.skip` when they cannot run.

`grepAtRev` distinguishes "no matches" (git exit 1 — an honest empty answer, and
for a completeness row a FAILURE) from "could not run", which git spells the
same way.

**`test/formats/s1disasm-pin-currency.test.ts`** — three rows, no peer needed:
the pin holds exactly the files its provenance records, byte for byte; `_incObj`
is still absent and the sidecar still says why; the markers are there.

⚠ **Not a tautology, and it is worth saying why**, because "a file matches its
own manifest" usually is one: the recorded ids are **s1disasm's** object ids,
and the row recomputes `sha1("blob <len>\0" + bytes)` from the fixture on disk —
git's own algorithm — so the comparison is against the peer's identifier, not
against something this repo derived from the same bytes a moment earlier.

**It does NOT check currency of the vendored bytes, on purpose.** These rows ask
whether Aurora handles a document; the document must not move under them, and a
whole-tree currency check against a live disassembly would go red on every
ordinary upstream commit. Noise on a gate is how a gate stops being read. The
one place currency IS the question has its own check, above. The sidecar's
revision is separately proven **published** by `aeon-fixture-currency.test.ts`'s
sweep, which now knows `s1disasm` (tip `origin/AS`).

## SECOND CURRENCY-SHAPED ROW IN THE CLASS-A SET: none found

The escape hatch said to stop and report before vendoring a file holding one.
The class-A set was re-read for the shape — *an assertion whose subject is the
disassembly's own completeness or shape, rather than Aurora's handling of a
document* — and `s1-sync-anims.test.ts` is the only file carrying it. The
neighbouring candidates were checked and are not it:

- `s1-object-art.test.ts`'s *"every linked art + mappings file exists on disk"*
  and `s1-adapter`'s *"resolves 100% of profile entries"* assert **AURORA's link
  table against a corpus**, not the corpus against itself. Pinned, they still go
  red when Aurora's profile names a file the corpus does not have — which is the
  proposition. They are the LOUD ANCHOR, and pinning makes them *more* decisive,
  not less, because the corpus stops moving.
- `s1-anim-sweep.test.ts` enumerates `_anim/*.asm` and parses each. Pinned, it
  asserts the parser handles every document in the pin; it never claimed the pin
  was the whole of `_anim` upstream.

**The distinguishing question, for whoever converts the next corpus:** would this
row still be able to go red if its input were frozen? If the answer is no, it is
a currency row and a pin will silently retire it.
