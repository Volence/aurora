## 2. What R3 compares, from aeon's source at the pin

aeon's `tools/clip_manifest.py`, lines 938-950 (the last line of the message elided):

```python
    keys = {}
    for cl in clips:
        cl.zone_key = keys.setdefault(cl.tree_key, len(keys))
    # one zone, one song: a region row is per ZONE, so two clips of a zone naming
    # different songs cannot both be honoured
    zone_music = {}
    for cl in clips:
        prev = zone_music.setdefault(cl.zone_key, (cl.music, cl.id))
        if prev[0] != cl.music:
            raise ClipManifestError(
                f"R3 {path}: clips {prev[1]!r} and {cl.id!r} are both {cl.donor} {cl.zone} "
                f"but name different music ({prev[0]!r} vs {cl.music!r}); a zone's region "
```

- **"Same zone" is the pair `(donor, zone)`**: `tree_key` is `(self.donor, self.zone)` (line 399). Two donors'
  `EHZ` are different zones.
- **The value compared is `raw.get("music") or None`** (line 394): absent and `""` are both `None`.
- **`music` is OPTIONAL** (the format comment, line 42, "OPTIONAL: a SONG_* NAME ... Absent = no song"). A zone
  whose clips all carry none passes: `None == None`. A present value must match `^SONG_[A-Z0-9_]+$` (lines 913-918,
  also reported as R3).
- **Absent is a value**: one clip of a zone with a song and one without is refused (`'SONG_S2_EHZ' vs None`).

So (a) is not only possible but forced: a new clip of a `(donor, zone)` the act already carries has exactly one
value R3 accepts, the one those clips share. Nothing made (a) impossible: every vendored manifest agrees per zone
(the census row below), "zone" is derivable from what the paste has (`donor` and `zone` are both on `NewClip`), and
no zone needs a choice (a zone new to the act takes no song, which R3 accepts). No STOP.
