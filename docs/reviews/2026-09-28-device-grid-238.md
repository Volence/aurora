### 1.2 The fix

- `strokeRectOnDeviceGrid` moved from `classic-overlays.ts` into `canvas/device-grid.ts`,

  that function plus a `getTransform()` read.

  - The marquee's dash is `[4, 4]` in the CSS frame it is now stroked in. That is the
    4 CSS px it always was.

    strokes.

### 3.2 The fix

**`segmentsOnDeviceGrid(ctx, dpr)`**, in `canvas/device-grid.ts`, is new and has the shape
of `MarkDrawCtx`. It is a path context in the caller's world units.

- It maps each straight segment to CSS through the transform in force, and strokes it
  under `setTransform(dpr)`.
- For a HORIZONTAL segment, the row goes on `snapStroke(y, w).at`. For a VERTICAL segment,
  the column goes on `snapStroke(x, w).at`. In both cases the ends go on `snapLength` and
  the width is `deviceStrokeWidth(w, dpr)`. This is the same rule
  `strokeRectOnDeviceGrid` and 237's surface line use.
- A DIAGONAL segment is drawn where it was, at its unsnapped CSS width. The rule is about
  device rows and columns, a slanted line crosses both, and no rule for it is invented.
- "Horizontal" means the other axis moves less than 1e-6 CSS px. The reason is that
  `angleNeedle` builds directions from `Math.cos`/`Math.sin`, and a quarter turn leaves
  about 6e-17 rather than zero. A row holds this.
- It draws one path per width, so the lens's many edges are still one stroke.

**The call sites:**

- `drawTileLens` takes an optional `dpr`. When it is given, the edges go through the
  adapter. Aeon's three lens callers pass nothing, so their picture is unchanged. The
  dpr-1 identity hash in §4 covers the map canvas.
- `drawPriority`, `drawObjects` and `drawStart` take a REQUIRED `dpr`, for the reason
  `drawCollision` gave at row 194: a default of 1 would be silently wrong. For
  `drawObjects` the parameter is inserted after `invZoom`.
- `drawCollision` hands `drawAngleMark` the adapter in place of `ctx`. The shared
  `drawAngleMark` in `core/` is untouched. Its other callers (aeon's `OverlayRenderer`
  and the legend swatch) still draw unsnapped. See Open.

## 7. The row 238 ruling: both edges on whole device pixels

The overseer ruled on the blocked item on 2026-09-28, under the owner's 2026-09-18 look
permission. The ruling:

- Every stroke rows 237 and 238 snapped has BOTH edges on whole device pixels at every dpr.
- None is softer at dpr 1 than master was.
- The mechanism is parity-aware centring: an ODD device width centres on a half-pixel, and
  an EVEN device width centres on a whole pixel. The half, full, half picture was a defect
  of the helper, not the ruled look.

### 7.1 The fix (`c6a93884`)

- **`snapStrokeEdges(cssAt, cssWidth, dpr)`** is new in `canvas/device-grid.ts`.
  - The width is `deviceStrokeWidth(cssWidth, dpr)`, as before.
  - For an odd width, the centre is `round(at x dpr) + 0.5`. That is the same answer
    `snapStroke` gives, so every 1 px line is unchanged, including row 237's 1 px ghost,
    which gave 200/200 again on screen.
  - For an even width, the centre is `round(at x dpr)`, a whole device pixel.
- **Where it is used:** `strokeRectOnDeviceGrid`, `strokeCssRectOnDeviceGrid`,
  `segmentsOnDeviceGrid`, and classic's surface line. The surface line is 1 px, always
  odd, so its answer is identical.
- **What is covered, by call site:**
  - MapViewport's ghost and marquee (2 px) and classic's selection box (2 px), all through
    the rect helpers;
  - classic's stamp-drag preview (2 px) and collision marquee (1.5 px, drawn 2 device px),
    through `strokeRectOnDeviceGrid`;
  - the start crosshair (2 px), the priority-lens edges and the axis-aligned angle mark,
    through `segmentsOnDeviceGrid`.
- **This repairs a regression row 237 shipped.** Row 237's stamp-drag preview and
  collision marquee, already on master, half-covered a device column at each edge at every
  dpr. At dpr 1 that is softer than the world-unit `2 / zoom` stroke they replaced, which
  covered two whole columns on an integer edge.
  - The stamp-drag preview is now pixel-identical to the pre-237 stroke at dpr 1
    (b.s1.12 in §7.3).
  - The collision marquee is NOT claimed identical. Before 237 it was 1.5 world-scaled
    CSS px, which is 1.5 device px at dpr 1 and soft on any edge. It is now 2 whole device
    columns. That is measured by unit rows only, not on screen.
- **`snapStroke` itself is unchanged.** So is every one of its pre-existing callers (§7.2).
- **The docblock sentence was false, and is corrected.** `canvas/device-grid.ts` said a
  2 px line "keeps the half-covered edges it has always had at dpr 1". The file docblock
  now says:
  - that holds only for the chrome that drew at `round(v) + 0.5` before it came to
    `snapStroke`;
  - it does not hold for world-unit outlines;
  - the chrome callers stay on `snapStroke` under their golden;
  - rows 237/238's helpers use `snapStrokeEdges`.
- **A measured consequence: the angle mark's stem.**
  - The stem's core is `1.25 x ARROW_WIDTH_SCALE` = 2 CSS px, an EVEN device width at
    every dpr.
  - Its casing is `3 x 1.6` = 4.8 CSS px. That rounds to 5, an ODD device width at every
    dpr.
  - With both edges of each on whole pixels, their centres sit exactly 0.5 device px
    apart. A row asserts that 0.5, where row 238's first pass asserted a shared centre.
  - The bar (1.25 core in a 3 casing, both odd) stays concentric.
