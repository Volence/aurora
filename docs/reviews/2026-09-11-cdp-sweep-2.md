## 1. The aeon copies, and how the two-zone copy was made

* **The checkout** was found through the resolver, `siblingPath('aeon')` in
  `test/support/sibling-root.mjs` (step 3, from this repo's `--git-common-dir`), never by a typed
  literal.
* **Its published tip**: `origin/master` = `b3db547e555d6881c16392ca9b9b1baab486be32`, read with
  `git rev-parse` before and after. One tarball was made from that SHA with
  `git -C <aeon checkout> archive -o <tar> <sha>` into a `mktemp -d` directory under `/tmp`. That
  is the only command that touched the checkout, and it reads the object store only.
* **Per run, two fresh copies** (C1, C2) are extracted from the tarball into `mkdtemp` directories
  under `/tmp`, and removed at the end. The harness refuses if a copy's path is the live tree.
* **The published tree is ONE zone (`ojz`) with ONE act (`act1`).** The loader was read first:
  every zone parses its own tileset file (`src/core/project/aeon/load.ts:508`), each act reads its
  `dataPath` section files plus the strip and bg paths, and a zone id with no effects wiring is
  recorded rather than fatal (`load.ts:757`). So, in each COPY only, `project.json` gains:
  * act `act2` in `ojz`: a byte copy of act1's data directory. This is what R5 needs, and it makes
    R1's control honest, because act 2 then draws exactly the picture act 1 does;
  * zone `zb` ("Sweep Zone B"), one act, a byte copy of act1's data, drawn with `zb_tiles.bin`,
    which is `ojz_tiles.bin` with every 4bpp pixel `v` replaced by `15 - v`. The file is raw 4bpp
    (`src/core/formats/tiles.ts`), so every tile differs. On screen, zone B is visibly another tile
    set; in the data, its word planes are identical to ojz act1's (both hash `2701596095`), which
    is exactly the hazard the refusal exists for: the same numbers, a different tile set;
  * a project NAME suffix, `(sweep C1)` / `(sweep C2)`. The window title carries it, so a run can
    see which copy is open. The name is not an id; zone and act ids are identical in both copies.
* The loaded copy listed all three levels (`Oracle Jungle Zone · act1`, `· act2`,
  `Sweep Zone B · act1`) in every run (row `0b`), and `zoneArtHash` read `628154474` for ojz and
  `1662671378` for zb (row `R4.0`).
* **CHUNK-STAMP-ACROSS-ZONES** (`docs/lens-findings.jsonl`) asks any parcel that adds a zone to read
  it first. Read. The second zone exists only in `/tmp` copies, nothing is committed with two zones,
  and no row here stamps a chunk.

## 3. How "on screen" was judged, and the rows

Every "painted" and every "unchanged" is read off a **screenshot clip of the map canvas box**,
decoded in the harness and compared pixel by pixel (`diff()` counts changed pixels and how many fall
inside a named box). A clip is only compared once **no toast is painted**, because toasts are
fixed-position and overlap the map's bottom edge. Store probes are printed beside the pixels, never
instead of them. Every gesture is `Input.dispatchMouseEvent` or `Input.dispatchKeyEvent` at an
integer pixel, after a hit test. `__dbg` is used for reads and for camera setup (`setView(0, 0, 1)`)
only. **Row `0c`, a null control**: two clips of the untouched map 0.9 s apart differ in 0 pixels,
so the map does not animate under these compares.

**"Paste mode is off" needed its own instrument.** `__dbg.aeon.pasteGhost()` publishes only while
pasting (`src/renderer/components/MapViewport.tsx:3814`), so its `pasting` field can never read
false. Instead: the paste branch of mousemove is tool-independent and publishes on every move it
handles, so real moves over the map that leave the report's `paints` counter where it was mean the
branch did not run. The control is the same moves while armed, which advance it.

## 5. The two harness defects, each a false red about the app

1. **The typed-path field was not empty (run 1).** After R3 opened C2 through Home's
   "…or type another project directory path" field, the field kept C2's path, and my click put the
   caret at its end. R6b's typing appended: `"/tmp/cdps2-C2-QFtuP5/tmp/cdps2-C1-EZURFW" is not a
   recognized project`, a red banner, and the whole workspace pushed down 66 px
   (`r6b-refusal-toast-full-run1.png` against `r6a-refusal-toast-full-run1.png`). Every later aim
   landed on other tiles, which read as "the paste writes nothing". Fixed: the field is read, then
   cleared with real keys; and every phase now refuses to run if the canvas box has moved from the
   one its aims were derived from. What the field held is itself an observation (O1).
2. **The control compared the whole clip (runs 1 and 2).** R3's Home round-trip control went red on
   21,900 px, all of them the coordinate readout bar (O2), none in the marquee or ghost box
   (`r3-before-open-full-run2.png` against `r3-after-home-trip-full-run2.png`). The control is about
   the marquee and the ghost, so it now reads those two boxes, and allows other changes only when
   every one lies inside the readout bar's own DOM rect while that bar flips `flex` to `none`.

Each was diagnosed from that run's own printed detail and captures before any rerun.

## 6. Observations, for the overseer, not acted on

* **O1. The switch-case typed-path field keeps the last path it opened.** Home is kept alive, so
  the field (`src/renderer/components/home/HomeTab.tsx:215`) still held `/tmp/cdps2-C2-…` when Home
  was shown again (runs 2, 3, 4 each printed it). A click puts the caret at the end, so a second
  typed path appends to the first and the open fails with a red banner. This is the shape seat A
  filed as F4: typing lands appended to a value the reader thought was gone. Not a row here.
* **O2. In paste mode, the map's coordinate readout stays hidden once the cursor leaves the map.**
  `onMouseLeave` hides it (`MapViewport.tsx:4453`) and the only line that shows it again (`:3993`)
  sits after the paste branch's `return` (`:3814`). Seen on every run at R3's control. Pre-existing,
  and unrelated to either fix.
* **O3. `pasteGhost().pasting` cannot read false** (published only while pasting). A future harness
  that asserts "paste is off" through it would pass vacuously. This sweep used the paint counter.
