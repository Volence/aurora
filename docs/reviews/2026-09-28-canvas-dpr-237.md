# Row 237: CANVAS-DPR-FOLLOWUPS-FROM-194, a scale change with no resize, and classic's strokes on the device grid

Branch `parcel/canvas-dpr-237`, from master `9eae300c`. Evidence files are in
`docs/reviews/237-canvas-dpr/`.

Row 237 took two items from row 194's Open section
(`docs/reviews/2026-09-28-classic-canvas-dpr-194.md`):

- **(a)** Neither the Sonic 1 canvas nor MapViewport re-sized its store when the display
  scale changed with no CSS resize. The fix is one shared listener in `canvas/device-grid.ts`.
- **(b) RULED** (overseer, 2026-09-28, under the owner's 2026-09-18T19:27:49Z look
  permission). Classic's strokes (ghost outline, marquee, collision marks) snap to the
  device grid through the SAME `snapStroke` / `snapLength` that MapViewport's chrome uses.
  The ruling allows no new stroke look.
- **(c)** is the owner's eye on real hardware. This parcel does not touch it.

## 2. The fix

### (a) `2aab0909`, `60c429d9`

- **`onDeviceScaleChange(listener, host?)`** in `canvas/device-grid.ts`.
  - It arms `matchMedia('(resolution: <dpr>dppx)')` for the current scale.
  - A list fires `change` only when its own answer flips, which happens once, when the
    display leaves that scale. So on each change the listener drops the old list's
    listener, arms a new one on the new scale's query, and then calls back with the
    new scale.
  - At most one listener per subscription is live. The unsubscribe removes whichever
    list is current.
  - The reading goes through `deviceScale`'s rule, now factored as `usableScale`, so an
    unusable value arms on `1dppx`.
  - With no window, or with no `matchMedia`, it does nothing and returns a no-op
    unsubscribe.
  - `host` is a parameter only for the fake-display tests.
- **ClassicLevelViewport.** The measure effect subscribes `measure` next to its
  ResizeObserver, and its cleanup unsubscribes. `measure` already re-sizes when
  `prev.dpr !== store.dpr`.
- **MapViewport.** The component adds `useEffect(() => onDeviceScaleChange(() => redraw()), [redraw])`,
  the same `redraw` its ResizeObserver calls. `redraw` re-sizes the map store first
  thing and ends in `drawCollisionPreview`, which re-sizes the ghost layer.
  - The first version also called `drawCollisionPreview()` explicitly. Planted out as
    Ma3, removing it changed nothing (55/55), so `60c429d9` removed the call. See §3.

### (b) `e0ef4746`

- **`strokeRectOnDeviceGrid(ctx, x, y, w, h, cssWidth, dpr)`** in `classic-overlays.ts`.
  - It maps the world rect to CSS through `ctx.getTransform()`. That transform is
    classic's `setTransform(dpr)`, then `scale(zoom)`, then `translate(-cam)`, all
    axis-aligned.
  - It strokes under `setTransform(dpr, 0, 0, dpr, 0, 0)` with
    `snapStroke(...).at` for the corner, `snapLength` for the size, and
    `snapStroke(...).width` for the line width. Then it restores the transform.
  - These are the calls `region-overlay.ts` and `screen-frame.ts` make.
- **Three outlines use it:** the stamp ghost (1 CSS px), the stamp-drag preview (2), and
  the collision marquee (1.5). The stamp-drag preview is not named in the ruling. It is
  the same kind of stroke on the same canvas (a cell outline), so it is included, and
  this is stated here rather than chosen silently.
- **The collision surface line** (`drawCollision`) is drawn the same way: its row on
  `snapStroke(..., 1, dpr).at`, its ends on `snapLength`, and its width
  `deviceStrokeWidth(1, dpr)` device px, the width row 194 already used.
- **Not changed.** The angle mark (`drawAngleMark`, which is shared with aeon's overlay),
  the collision fills (they are fills, not strokes), and the object, start, priority and
  loop-glyph strokes, which the ruling does not name. See Open.

## 6. Open

- **(c) TAG(owner): real hardware.** Everything here ran under Xvfb, with a forced or
  emulated factor. Two checks remain:
  - dragging the window between monitors at different scales should leave the map sharp
    with no resize;
  - the Sonic 1 ghost, marquee and collision lines should look like the aeon map's lines
    at 125% to 150%.
- **dpr 1 changed too, by design.** At dpr 1 the ghost outline used to be 1 CSS px
  centred on the cell edge, so it half-covered two columns (`4c6582` in both, Mb3 at 1).
  It now covers the cell's first column (`8ebef2`).
  - This is snapStroke's `round(v) + 0.5` at dpr 1, the rule MapViewport's chrome has
    always used.
  - Unlike MapViewport's chrome, classic's dpr-1 picture is therefore NOT byte-identical
    to master's. The ruling asked for the shared look, not for dpr-1 identity.
- **The shared rule's right and bottom edges.**
  - `snapStroke(x).at + snapLength(w)` puts the far edge's 1 px line on the device column
    just PAST the cell (the next cell's first column), while the near edge's line sits on
    the cell's own first column.
  - The same is true of every rect MapViewport's chrome draws this way.
  - Row 194's harness shows it: the box is `48..432` against the cell's `48..431`.
  - It was not changed, because the ruling says no new stroke look.
- **Even-width strokes keep half-covered edges, by the shared rule.**
  - The stamp-drag preview (2 CSS px) and the collision marquee (1.5 CSS px, which
    `deviceStrokeWidth` draws as 2 device px) are an even number of device px wide,
    centred on a device half-pixel. So they cover half, whole, half.
  - `device-grid.ts` documents this: "a 2 px line keeps the half-covered edges it has
    always had at dpr 1".
  - The on-screen proof in §4 is the 1 CSS px ghost outline. The brief's "no
    half-covered column" holds for odd widths only, which is a consequence of the ruled
    rule. It is not claimed for the two even-width strokes.
- **Strokes this parcel did not snap:**
  - Classic's object boxes, the selection box, ring outlines, the start marker, the
    priority-lens edges and the loop glyph. These are outside the ruling's list.
  - The angle mark, whose `drawAngleMark` is shared with aeon's overlay.
  - MapViewport's own stamp ghost and marquee in `drawCollisionPreview`. They are still
    drawn in world units at `2 / zoom`. This is a finding: those two are not on the
    device grid either, although MapViewport's region, frame and guide chrome is.
- **Other dpr-sized canvases.** `CollisionLegend` and `AnchorSweepPreview` size their
  stores from `deviceScale()` but do not subscribe to `onDeviceScaleChange`, so they
  still keep their old store until their next redraw. They are outside row 237's two
  canvases.
- **Not measured:**
  - any real monitor move;
  - fractional factors other than 1.5 on screen for (b) (the node rows cover 1.25, 1.35,
    2 and 3);
  - `npm run harness:dpr-guides-offset` on this build. MapViewport gained only the
    listener, but that harness's emulation step will now also trigger a listener
    repaint. It was not re-run.
