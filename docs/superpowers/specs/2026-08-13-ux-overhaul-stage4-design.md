# Aurora UX Overhaul — Stage 4 Design Spec

**Date:** 2026-08-13
**Status:** Approved pending final user review
**Parent spec:** `docs/superpowers/specs/2026-08-12-aurora-ux-overhaul-design.md` (§12.4 is this stage)
**Carry-forward input:** `docs/superpowers/plans/2026-08-13-ux-overhaul-stage4-notes.md`
**Baseline:** Stage 3 end — 156 test files / 1344 passed / 2 skipped, `tsc --noEmit` clean

## 1. Scope

Four pieces, one branch, staged internally (§8):

| Piece | What |
|---|---|
| **A. Classic re-home** | `ClassicProjectView` and its 18-file subtree become facet modules in the shared `LevelWorkspace` |
| **B. Undo unification** | The undo-bus + three-history arrangement is replaced by per-document stacks on a generalized `DocumentHistoryHub` |
| **C. Guard + debt cleanup** | Three parallel dirty-guard flows collapse to one helper; assorted carry-forward debt; TabStrip a11y |
| **D. Aeon BG bridge** | Editor↔engine BG round-trip, plus an editable tile-band animation editor |

**Exit criterion** (from parent §12.4): facet parity — same task, same UI, regardless of which engine the open project is. The undo-bus is *replaced*, not bridged.

## 2. Corrections to prior documents

Three claims in the parent spec and the Stage-4 notes were investigated and found wrong. They are corrected here; the parent spec is not edited (this document supersedes it on these points).

### 2.1 Aeon's tier vocabulary — parent §4 line 48

Parent §4 says "The classic Composer's Chunk › Block › Tile drill-down becomes **the** Art facet pattern for both engines." This cannot be taken literally: **aeon has no 16×16-px block tier, and the two ladders do not correspond.**

Authoritative source: `aeon/engine/system/constants.emp` + `aeon/docs/LEVEL_EDITOR_SPEC.md` §3.

| Aeon tier | Pixels | Nature |
|---|---|---|
| Section | 2048×2048 | 16×16 grid of blocks |
| **Block** | **128×128** (16×16 tiles) | 768 B: 256 nametable words + collision planes A/B |
| Tile | 8×8 | VDP word, addressed **directly** from the block nametable |

Aeon's "block" is what S1/S2 call a *chunk*. Aeon blocks are **positional, not pooled** — `aeon/tools/ojz_block_gen.py` slices them out of Aurora's flat section nametable at build time (entry *i* = grid slot *i*; no ids, no reuse-by-id). Aurora is therefore correct to store sections flat; the block tier is a build artifact, not an editing entity. `S4Project.ChunkDef` is a free-form editor stamp of arbitrary `widthTiles × heightTiles` with no engine tier at all.

The parent spec's wording most likely originated in aeon's own stale docs (§9.1).

### 2.2 The BG export transform — Stage-4 notes §"Aeon BG store bridge"

The notes assumed the export must invert `inject_editor_bg.py` (row-major→column-major, local→VRAM-absolute at `BG_TILE_BASE_SLOT`, BE byte-length tile header). It must not. **Aurora writes the JSON override, not the binaries**; `inject_editor_bg.py` still performs that transform downstream. Aurora's in-memory BG is already row-major with blob-local indices — the exact convention `editor_bg_override.json` uses — so the export is effectively identity:

```ts
{ layout: Array.from(act.bgLayout), tiles: act.bgTiles.map(t => Array.from(t.pixels)) }
```

Verified: the shipped `editor_bg_override.json` is byte-identical to the `ojz_bg_ingame-forest-v15-*` library entry Aurora already holds.

### 2.3 Band animation phases are derived, not authored

A band's 8 `phases` banks are not hand-drawn frames: bank *k* is the pattern pre-shifted *k* pixels, generated by `aeon/tools/forest_bg_gen.py`. The editor authors **one pattern** plus driver/rate parameters; Aurora derives the banks (§7.2).

## 3. Facet architecture

### 3.1 Engine-neutral shell, engine-keyed canvas

`facetModules` stays keyed by facet id and holds the shared slots. A second registry, keyed `(engine, facetId)`, resolves the Canvas slot only:

```ts
facetModules.get('layout')          // { ToolDock, ToolOptions, RightPanel, StatusBar } — shared
facetCanvases.get('s1',   'layout') // ClassicLevelViewport
facetCanvases.get('aeon', 'layout') // MapViewport
```

Everything else — tool dock, tool vocabulary, right panels, status bar, keybindings, undo — is engine-neutral over small adapters. The two viewports (910 and 1542 LOC of separately-evolved canvas code) stay intact; merging them is explicitly *not* in scope.

Parity is enforced structurally by the shared-slot contract, and behaviorally by the §10 parity test.

### 3.2 Engine-neutral capability source

`LevelWorkspace` currently hardcodes `useProjectStore` (aeon) for `capabilities.facets`. New module `src/renderer/state/open-project.ts` exposes `useOpenEngine()` and `useOpenCapabilities()`, reading whichever of `projectStore` / `classicProjectStore` is open. The s1 adapter already grants `['layout','art','objects','collision','palette']` (`src/core/project/s1/index.ts`); that grant was simply never read.

No store merge. The two project stores stay separate; the selector module is the seam.

### 3.3 Profile-declared art tier ladder

The Art facet's drill-down depth comes from the profile, not from hardcoded tabs:

```ts
interface ArtTier {
  id: string
  label: string
  pixelSize: number | null   // null = free-form dimensions
  pooled: boolean            // shared indexed pool with stable ids?
}
```

```ts
s1.artTiers = [
  { id: 'chunk', label: 'Chunk', pixelSize: 256, pooled: true },
  { id: 'block', label: 'Block', pixelSize: 16,  pooled: true },
  { id: 'tile',  label: 'Tile',  pixelSize: 8,   pooled: true },
]
aeon.artTiers = [
  { id: 'chunk', label: 'Chunk', pixelSize: null, pooled: false },
  { id: 'tile',  label: 'Tile',  pixelSize: 8,    pooled: true },
]
```

Tiers an engine lacks do not render — the same "no dead chrome" rule the parent spec §4 already applies to facets. S2/S3K/SCE profiles later declare their own ladder with zero shell edits.

### 3.4 Pooling drives affordances

Affordance sets are selected by `tier.pooled`, not by engine identity and not by tier depth. This is a general rule, not a special case for aeon:

| `pooled: true` | `pooled: false` |
|---|---|
| usage counts | (meaningless — omitted) |
| shared-edit banner | — |
| Duplicate-before-edit | marquee copy/paste, save-marquee-as-chunk |
| id chips | explicit *Save to library* + dirty badge |

Aeon's only pooled tier is `tile`, so aeon keeps the clipboard/staging/Save-to-library flow built in Stage 3. Classic keeps its pool semantics (usage index, `SharedBanner`, Duplicate). Neither engine inherits the other's wrong affordances.

### 3.5 Shared Art facet: aeon substrate, classic navigation

The substrate is aeon's: the open-document model, the 11-tool store-backed dock, `PixelEditController` / `PixelViewport`, copy-on-write staging, marquee clipboard, transforms, mirror/dither/pixel-perfect.

Classic contributes what it does better — **navigation**: a `Chunk $12 › Block $0A › Tile $3F` breadcrumb, the descent gesture (click a cell → open that child as a doc), and ascent by breadcrumb. Both are shared code driven by `artTiers`.

Classic's `ClassicComposerDock` is retired: it is a permanently docked composer, which parent §4 explicitly bans. The composer *becomes* the Art facet.

Two classic-only concepts survive as tier/profile properties, not branches: **tile locking** (`editableTileRange` — anim-art slots and appended tiles are view-only) and **solidity** (2 bits on the chunk↔block edge, plus the block-indexed `colind` height table).

Classic's palette-line selector is a *view lens* in `TileTab` and a *writer* in `BlockTab`; aeon's is a global paint modifier with a dedicated `palette-apply` tool. The unified facet keeps both meanings distinct: the line picker in tool options is the paint modifier (aeon's semantics, now available to classic), and per-cell palette assignment stays a cell-property edit (classic's `BlockTab` semantics, expressed as `palette-apply`).

### 3.6 One tool vocabulary

Classic's three inline chips map onto the existing `EditorTool` union — `pan → view`, `stamp → stamp-chunk`, `object → place-object` — and move into the shared `MapFacetDock`. `TileTab`'s local pencil/fill `useState` is absorbed by `artStore`.

The profile declares which tools each facet offers; `FACET_TOOLS` becomes the default, intersected with the profile. Classic's Layout facet therefore shows no marquee / paint-tile / paint-block, without any engine branch in the dock.

Classic's plane (`FG`/`BG`) and overlay (Collision / Angles / Objects / Start) toggles are today **viewport-local `useState`** — unreachable from outside the component. They move to `editorStore.editingLayer` and `viewStore`, which is what makes the shared plane control and overlay toggles work for both engines.

### 3.7 Classic's orphan surfaces

| Today | Becomes |
|---|---|
| `ZoneActTree` panel | **deleted** — the explorer's Levels group (Stage 2) already does this |
| `ResolutionReportPanel` | Project Setup tab (parent §7: report promoted from readout to editor) |
| `ChunkPicker` bottom strip | Layout facet right panel, merged with aeon's `ChunkLibrary` |
| `ClassicComposerDock` | **is** the Art facet (§3.5) |
| `Toolbar` | **deleted** — workspace header + sprite-doc header take over |
| `LegacyWorkspace`, `ClassicProjectView` | **deleted** — `LevelWorkspace` serves both engines |

Deleting `Toolbar` also resolves the notes' carry-forward that switching acts from the sprite-doc pane's app bar navigates the whole app away from the sprite doc: that selector was aeon's, reachable only from that pane.

Pure helpers already extracted and unit-tested — `viewport-math.ts` (265), `classic-overlays.ts` (259), `composer-math.ts` (88), `report-grouping.ts` (38) — port unchanged.

## 4. Undo and history

### 4.1 One interface, one hub

```ts
interface UndoStack {          // argument-free: each stack binds its own target
  readonly canUndo: boolean
  readonly canRedo: boolean
  undo(): void
  redo(): void
  clear(): void
  onChange(cb: () => void): () => void
}
```

Argument-freeness is the crux. Aeon's `EditHistory` takes `level: S4Level` on every call, which is precisely why the hub could not hold the other two histories; it gains a `() => S4Level` supplier at construction instead.

`DocumentHistoryHub` becomes `Map<string, UndoStack>` with factories registered by doc-id prefix — the same pattern as `src/core/shell/registry.ts`:

```
level:<zone>:<act>          layout doc   — fg/bg grids, objects, start
zoneart:<zone>              zone art doc — chunks, blocks, tiles, palettes
doc:sprite:<engine>:<ref>   sprite doc
```

### 4.2 Undo follows the focused facet

Identical rule for both engines:

| Focused | Stack |
|---|---|
| Layout / Objects / Collision facet | `level:<zone>:<act>` |
| Art / Palette facet | `zoneart:<zone>` |
| Sprite doc tab | `doc:sprite:<engine>:<ref>` |

`activeHistory()` — keyed off `projectStore.currentActId`, aeon-coupled — is replaced by `focusedHistory()`, keyed on `sessionStore.activeId` + `workspaceStore.facetFor(activeId)`.

**User-visible behavior change:** today a palette or tileset edit made from act 1 is undoable only from act 1's tab. After this it is undoable from any act tab of that zone, via the Art or Palette facet. This is parent §10 working as intended, and it is a change worth calling out in the smoke-test script.

### 4.3 Classic's snapshot splits by domain

`ClassicSnapshot` (whole `LevelDoc` + dirty + chunkVersions + chunkEpoch) splits into:

- `ClassicLayoutSnapshot` — fg/bg grids, objects, start, the layout/object dirty domains
- `ClassicArtSnapshot` — chunks, blocks, tiles, palettes, `chunkVersions`, `chunkEpoch`, the art/palette dirty domains

Cheap, because `LevelDoc` is immutable-by-convention and structurally shared: each snapshot holds references to the slices it owns. `commit()` splits into `commitLayout` / `commitArt`.

**Required plan step:** audit every `commit()` call site in `classicLevelStore` (~15) and assign each a domain. Any site touching both domains becomes an explicit compound that pushes to both stacks and undoes as a pair. This audit is the highest-risk item in piece B and must not be done by inspection alone.

### 4.4 Sprite store becomes multi-document

`spriteStore` today holds one working document, so two open sprite tabs share one `spriteHistory` singleton. It becomes multi-document: state keyed by sprite doc ref, one `SpriteHistory` per doc in the hub, tab close disposing both.

This also resolves a carry-forward: the sprite-doc dirty confirm currently offers Discard/Cancel only, because save paths were context-dependent (`s1ArtSource != null`). With per-doc state, "save this doc" is well-defined, so the confirm gains **Save**.

### 4.5 Deletions

- `src/core/editing/undo-bus.ts` (20 LOC) — 3 `registerRedoClearer` registrations, 3 `invalidateSiblingRedos` fire sites. With per-document stacks there are no siblings to invalidate.
- `src/renderer/state/sprite-undo.ts` (88 LOC) — the recency-merge coordinator and its module-level `useSessionStore.subscribe` side effect.
- `src/core/editing/edit-seq.ts` (18 LOC) — dead once recency merging is gone.
- `Toolbar`'s `isSpriteDoc ? spriteMode* : …` branches (both blocks), with `Toolbar` itself (§3.7).

The three repaint clocks — `editorStore.historyVersion`, `classicLevelStore.historyTick`, `spriteStore.historyTick` — collapse onto one hub-level `onChange`.

`hub.dispose(docId)` gets wired to tab close. It has no production caller today; per-document stacks make a closed doc's leaked stack a real memory concern.

## 5. Guards and flow unification

Three parallel ask→save/discard→proceed flows exist: the tab-activation act-switch guard, `project-open-guard`, and `ProjectSetupTab`'s local one. They collapse onto:

```ts
confirmDirtyThenProceed({ scope, supersede, onSave, onDiscard, onCancel })
```

`openPath`'s flow deliberately has no supersession counter. That becomes an explicit `supersede: false` argument rather than an accident of implementation — the behavior is preserved, the intent is now stated.

`ProjectSetupTab`'s same-directory reopen currently runs a narrower confirm checking `classicDirty` only; it widens to the shared dirty aggregate.

`agent-handler`'s classic-open-project command fails closed on dirty state, permanently blocking automation. It gains an explicit `force: 'save' | 'discard'` flag; absent the flag it still fails closed.

The open-guard's abort toast says "see earlier save errors", which is misleading in the sprite-checkout-still-open case where no earlier error exists. Fixed.

## 6. Smaller debt (piece C)

- `Explorer.tsx`'s activate router is five if/else branches; classic's re-home adds more, so it becomes table-driven dispatch.
- `viewStore` gains `reset()`; the one test that sets store defaults via `setState` uses it.
- TabStrip accessibility: `role="tab"` / `aria-selected` / keyboard navigation, plus a `ConfirmDialog` focus trap. Deferred since Stage 2 watch-list gap #3; lands here.
- `FacetBar`'s pills stay intentionally bespoke (parent §11 calls for facet-switcher distinctness from generic chips). Not debt — noted so it is not "simplified" into `Chip`.

## 7. Aeon BG bridge and band editor (piece D)

### 7.1 Bridge, both directions

**Load chain**, first hit wins:
1. editor act-BG file (`<dataRoot>editor/<zone>_<act>_bg.bin` + `_bg_tiles.bin`)
2. `games/sonic4/data/editor_bg_override.json`
3. generated `zone_bg.bin` + `bg_tiles.bin` — normalized: column-major→row-major, `−BG_TILE_BASE_SLOT`, strip the BE byte-length header

**Save** writes `editor_bg_override.json` from the act's active BG using the identity transform (§2.2), preserving `palette` / `palette_line` when present and emitting `anims` from the band model (§7.2).

**Clobber protection** is a baseline hash captured at load:

| On-disk vs baseline | Aurora BG | Action |
|---|---|---|
| unchanged | — | write |
| changed | clean | re-import (external edit wins) |
| changed | dirty | conflict prompt |

**Library normalization asymmetry fixed:** `normalizeBgLayout` runs in the BG-library load path too, matching the act-default path. It is idempotent, so editor-saved local entries pass through unchanged, while engine-convention or hand-made entries stop silently misrendering as `base+n` past the 448-tile blob.

### 7.2 Band model

```ts
interface BgBand {
  cols: number                                    // pattern width in tiles
  rows: number                                    // vertical period in tiles
  driver: 'camera_x' | 'camera_y' | 'timer'
  rateShift: number                               // 1px of travel per (1<<rateShift) driver units
  pattern: Tile[]                                 // cols*rows tiles = phase 0
}
```

Derived at export, never authored: `slot_base` (running cursor — bands pack contiguously from local slot 0 in list order), `pattern_px = cols * 8`, `col_shift = log2(rows * 32)`, and `phases[0..7]` (bank *k* = pattern shifted *k* px).

**Plan-time verification required:** confirm the shift axis per driver against `aeon/tools/forest_bg_gen.py` before implementing the bank generator. `camera_x` is presumed horizontal; this is not to be assumed in code.

### 7.3 Which rows animate is emergent

A band has no authored row range. Cells animate because the layout points at that band's slots. The editor therefore **visualizes** the affected region — highlighting every layout cell that references band slots — rather than asking for a range.

### 7.4 The renumber hazard

Band patterns must occupy local slots `[0, Σn)`, contiguously, before any static tile. Adding or removing a band therefore renumbers the entire static tile blob and rewrites the layout. This must be **one automatic, single-undo command**. It is the main correctness risk in piece D and gets dedicated tests.

### 7.5 Live invariants

Shown Project-Setup-style with status lights, validated on every edit:

- ≤ 4 bands (`BGANIM_MAX_BANDS`)
- `rows * 32` a power of two → `rows ∈ {1, 2, 4, 8, 16}`
- `pattern_px == cols * 8`
- bands contiguous from local slot 0
- Σ(band tiles) + static tiles ≤ **448** — imported from `aeon/tools/vram_map.py`, **never restated** (per the "four-copies-of-448 incident", `aeon/docs/DEFERRED_WORK.md:879`)
- ROM cost `8 · cols · rows · 32` bytes per band, displayed live

The 44-byte `bganim_band` record has two authors — `aeon/tools/inject_editor_bg.py` and `aeon/engine/level/bg_anim.emp` — and Aurora becomes a third. Any format change edits all three.

### 7.6 Stale BG constants in Aurora

`src/renderer/agent/agent-handler.ts` has `BG_TILES_HIGH = 32` and `BG_MAX_TILES = 512`; both are wrong (all 64 rows are live; the ceiling is 448). `get-bg` reports `height: 32` unconditionally and `set-bg` rejects any layout that is not 2048 words — so the agent path **cannot author the 64-row BG the library already contains**. Fixed here. `src/core/formats/bg-tiles.ts`'s "the engine's fixed 64x32 Plane B" comment is likewise stale.

## 8. Internal staging

One branch, six steps, mirroring Stage 3's rhythm. Each step ends green (`tsc` clean, suite passing).

1. **Foundations** — `UndoStack`, hub generalization, `focusedHistory()`, open-project selectors, profile `artTiers` + tool declarations, facet-canvas registry. *No UI change.*
2. **Undo migration** — aeon onto the hub by facet; classic domain split (with the §4.3 call-site audit); sprite multi-doc store; delete undo-bus / sprite-undo / edit-seq.
3. **Classic into the workspace** — Layout / Objects / Collision facets, tool vocabulary merge, plane + overlay to stores, orphan panels rehomed, `LegacyWorkspace` / `ClassicProjectView` / `Toolbar` deleted.
4. **Shared Art facet** — tier ladder, breadcrumb descent, pooled/unpooled affordances, classic composer retired onto the aeon substrate.
5. **Guards + small debt + a11y.**
6. **BG bridge + band editor.**

## 9. Companion work outside Aurora

### 9.1 Aeon doc corrections (separate aeon commit)

Doc-only, landed independently of the Aurora branch:

- `aeon/docs/ENGINE_ARCHITECTURE.md` §4.3 (~line 2246): "Each block contains a 2×2 grid of nametable words (8 bytes)" — wrong; shipped format is 256 words / 512 B.
- `aeon/docs/ENGINE_ARCHITECTURE.md` §8.1 (~lines 3683-3692): narrates the S2 tile → 16×16-px block → 128×128 chunk vocabulary as aeon's, and claims "the runtime never sees them". The runtime very much sees a block; it just means 128×128.
- `aeon/docs/LEVEL_EDITOR_SPEC.md:251`: "rows 32-63 are init-only" — stale; all 64 rows are live (`ENGINE_ARCHITECTURE.md:1621`, NEW-5, 2026-08-05).

These are the likely origin of the parent spec's §4 misstatement (§2.1).

### 9.2 Collision cell geometry — verify before acting

Aurora's `chunkCellCount = (w>>1) * (h>>1)` yields 16×16-px collision cells in both axes. The engine is `BLOCK_COLL_COLS = 16`, `BLOCK_COLL_ROWS = 8` per 16×16-tile block — full column resolution, halved vertically (`aeon/engine/system/constants.emp:632-633`; `LEVEL_EDITOR_SPEC.md:510`). `aeon/tools/ojz_strip_gen.py:1514-1568` reads the editor file as "one per 8px tile column × 16px collision row", agreeing with the engine, not with `chunkCellCount`.

**Plan step:** check `src/core/collision/collision-cell-word.ts` and the `.collattr.bin` serializer against the engine before assuming a bug — Aurora's serializer may already compensate. If it is real, it affects the Collision facet's parity work and is resolved inside this branch.

## 10. Testing

- **Facet parity** (parent §13): a checklist-style integration test walking an s1 project and an aeon project through identical task scripts — open level, stamp chunk, place object, edit palette, descend the art ladder — asserting the same component tree shapes render.
- **History hub:** factory registration and prefix routing; per-document isolation (an edit in one doc never touches another's redo stack); `dispose` on tab close.
- **Classic domain split:** each audited `commit()` call site lands in the expected stack; compound edits undo as a pair.
- **Sprite multi-doc:** two open sprite docs keep independent histories and dirty state.
- **BG round-trip:** golden test — Aurora's exported override, run through a TS mirror of `inject_editor_bg.py`'s forward transform, byte-matches the checked-in `zone_bg.bin` / `bg_tiles.bin`.
- **Band invariants:** all §7.5 constraints; the §7.4 renumber is atomic and single-undo.
- **Guards:** each of the three collapsed flows preserves its prior behavior, including `openPath`'s `supersede: false`.

Verbatim-port tasks (the classic viewport, the classic overlays) are parity-audited hunk-by-hunk against their originals rather than trusted by inspection — the discipline that caught real defects in Stage 3.

## 11. Out of scope

- Merging the two viewports into one canvas over a shared level abstraction (§3.1).
- Promoting aeon's 128×128 block to an editing entity (§2.1) — that is an engine-format change.
- Tab drag-reorder (§6).
- Aeon lazy act loading (still eager, untouched since Stage 3).
- Classic sprite-doc restore of an object not linked in the currently loaded zone — accepted v1 edge case.
- Everything in parent §14.

## 12. Process

- Branch `feature/ux-overhaul-stage4`, worktree `.claude/worktrees/ux-stage4`.
- **Worktree tripwire** (held for all of Stage 3, zero master incidents across ~20 subagent runs): subagent shells start in the main tree, so every Bash call is cd-prefixed, all paths absolute to the worktree, and each work unit ends with a master-HEAD-unmoved check.
- Two-stage review per task. Implementer skepticism of the plan text is load-bearing — a Stage 3 implementer, not a reviewer, caught the `session-lifecycle.ts` restore-ordering hazard.
- Commit style `type(scope): summary`, single line, no trailers.
