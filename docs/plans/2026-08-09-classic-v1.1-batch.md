**Goal:** Close the gap to the full "HyperSonic" feature set for S1 projects: objects render their real sprites, all level-art layers (tiles/blocks/chunks) are editable in a purpose-built composer dock with shared-structure UX, sprite editing is reachable from the object UI, plus the approved polish list.

**Key design decision (user-ratified):** level-art editing lives in a **self-contained composer dock inside the classic project view** — NOT wired into aeon's Art mode. S1's strict shared tile/block/chunk semantics get purpose-built UX: usage counts everywhere, shared-edit warnings, duplicate-then-edit, capacity-aware creation (chunks ≤ 127 — layout byte masks bit 7 for loops; blocks ≤ $400; tiles bounded by the act pool).

## Task B6 — LevelArt-backed + offset-art object rendering

Closes the last object-art gap in the classic view: the two families B5 bucketed as
"needs a separate pipeline" now render. Coverage on GHZ1 went from **188/214 drawn (23

**SonLVLAPI offset semantics (verified against source).**
- `ObjectHelper.LevelArt` (`SonLVLAPI/ObjectHelper.cs:88`) = `LevelData.TileArray`, the
  whole level tile blob; `LevelData.ReadFile("LevelArt", …)` (`LevelData.cs:2024`)
  returns it and `MapASMToBmp` indexes it exactly like a standalone art file. So a
  LevelArt object's mappings tile indices point straight into the act's VRAM-ordered
  tile pool — which is precisely `LevelDoc.tiles`.
- The XML `<ArtFile offset="…">` value is in BYTES and is fed to
  `MultiFileIndexer<byte>.AddFile(bytes, offset)` (`ObjectDefinition.cs:709`), then
  `art.ToArray()` is passed to `MapASMToBmp`. `MultiFileIndexer` (`MultiFileIndexer.cs`)
  yields `combined[i] = data[i − offset]` (index getter line 79; `Count = max(offset +
  len)`), so a positive offset prepends `offset` blank bytes and a negative offset drops
  the first `-offset` bytes. Confirmed against the Tiles indexer, which divides the same
  attribute by 32 (`LevelData.cs:488`) — offsets are byte counts, always multiples of 32.

### B6 deviation notes
- **`tileIndexOffset` stored in TILES, applied in BYTES.** The field is the SonLVL byte
  `offset ÷ 32` (all real offsets are 32-multiples); `objectArtTiles` multiplies back by

  documented on the type and in the `off()` helper.

- **Dual/multi-art defaults ($45, $66) remain unlinked** — genuinely need a multi-file
  per-image art indexer (compositing distinct art files), which the single-source +
  offset model does not cover. Kept as honest hex-fallback with a reason in the curation.
