**Goal:** Close the gap to the full "HyperSonic" feature set for S1 projects: objects render their real sprites, all level-art layers (tiles/blocks/chunks) are editable in a purpose-built composer dock with shared-structure UX, sprite editing is reachable from the object UI, plus the approved polish list.

**Key design decision (user-ratified):** level-art editing lives in a **self-contained composer dock inside the classic project view** — NOT wired into aeon's Art mode. S1's strict shared tile/block/chunk semantics get purpose-built UX: usage counts everywhere, shared-edit warnings, duplicate-then-edit, capacity-aware creation (chunks ≤ 127 — layout byte masks bit 7 for loops; blocks ≤ $400; tiles bounded by the act pool).

## Task B3 — Composer dock

- `ClassicComposerDock` in the classic view, three tabs sharing one selection context:
  - **Chunk tab**: 16×16 block-grid editor for the selected chunk (from picker/eyedrop); paint = pick block (mini block-palette with thumbnails + usage counts) + flips + solidity (S1 single-plane, 2 bits); one `classicEditChunkCells` per gesture. "Duplicate chunk" (new id ≤ $7F or refuse with message), "New blank chunk".
  - **Block tab**: 4-tile composer (tile picker from the act pool with usage counts, flips, palette line, priority); one `classicEditBlock` per commit. Duplicate/new block (≤ $400).
  - **Tile tab**: 8×8 pixel editor (16-color row from the act palette; pencil only v1 — no full aeon tool suite); one `classicEditTiles` per stroke; anim/gap tiles shown locked with the existing rejection reasons surfaced pre-emptively.
- Shared-structure UX: usage counts on every entity ("used in N chunks / M cells"); an inline warning banner when editing anything used >1 place; counts computed by a pure indexed helper (tested) with invalidation on the relevant commands.
- Viewport/picker/thumbnails all refresh via the existing chunkVersions/epoch keying (tile/block edits already bump the epoch).
- Tests: usage-index helper; per-tab gesture→command wiring (one undo step); duplicate/new capacity refusals; composer honors engine-id space (chunk $00 not editable).

**B4 deviation notes:**
- **MCP palette tool named `set_level_palette`, not `set_palette`.** The aeon
  `set_palette` already owns that name in the flat `EDITOR_METHODS` registry and MCP
  `registerTool` throws on a duplicate name, so the classic palette tool takes a
  distinct role name (it also legitimately differs: it allows palette line 0). `set_start`
  kept its planned name (unique). Documented in editor-methods, MCP.md, and the ROADMAP.
- **Loop-flag layout-cell validation was tightened, not merely "confirmed".** The plan
  expected `classicSetLayoutCells` to already accept a raw loop-flagged byte; in fact
  only `validateLevelDoc` (structural) did — the command's per-cell guard capped at
  `doc.chunks.length` and would have rejected `id | $80`. The guard now validates the
  MASKED engine id (`& 0x7f`) against the pool while accepting the full 0..$FF byte, so
  the loop bit rides through to save (render/collision already mask `& 0x7f`). A
  byte-level store test pins that the raw flagged byte is stored.
- **Reusable color picker extracted to `GenesisColorSliders`** (art-shared) rather than
  refactoring the aeon `PaletteEditor` — reuses the CONTROL idiom decoupled from the
  aeon stores without risking aeon regressions (as the plan directed: "reuse the picker
  CONTROL only, not the aeon-coupled editor").
- **Store `classic-commands.ts` extraction intentionally NOT done** (kept B4 scoped, per
  the controller's instruction; noted for a later batch).

**Deliverable 2 — Subtype rules (`src/core/project/profiles/object-subtype-rules.ts`).**
`resolveObjectPieces(id, zone, subtype) → { pieces, link } | null` (null = no rule →
existing single-frame path). Each rule cites its SonLVL source:
- **Bridge $11** (GHZ/Bridge.cs): N = `subtype & 0x1F` logs, `st = -(N*16)/2`, log i at
  `dx = st + 16i` — centred on the origin.
- **Monitor $26** (Common/Monitor.xml): low-nibble Contents → Monitor.asm frame
  (0→1,1→3,…9→11); the shell+icon are composited inside each frame (one piece).
- **Spring $41** (Common/Spring.xml): Direction bits4-5, Color bit1 → up/down use
  Spring Horizontal.nem frame 0, horizontal uses Spring Vertical.nem frame 3; pal 0/1.
- **Spikes $36** (Common/Spikes.xml): Type bits4-6 → Spikes.asm frame 0..5.
- **Spiked Pole $17** (GHZ/SpikedPole.cs): N = min(0x16, subtype) segments cycling
  frames 0..7 at `dx = -(N<<3) + 16i`.
- **Swinging Platform / Spikeball $15** (GHZ/SwingingPlatform.cs; applied GHZ/MZ/SLZ/SBZ):
  anchor frame2 + `subtype&0x0F` chain links (frame1, +16px each from y=16) + platform
  frame0 at y = 8 + 16·length.
- **SYZ Spikeball Chain $57** (SYZ/SpikeballChain.cs): `(subtype&0x0F)+1` balls stacked up.
- **Newtron $42, Breakable Wall $3C, Wall Barrier $44** (GHZ XML): frame (+palette for
  Newtron) by subtype.
- **Egg Prison $3E, Point Bonus $7D** (Common XML): frame by subtype.

Composer `composeObjectFrames` (pure, in `object-sprite.ts`) renders each piece frame,
applies per-piece flips, unions bounds, and normalises the origin so `objectFrameRect`
treats the composite exactly like a single frame.

**Piece-order correctness fix (found via the monitor render).** SonLVL/S1 hardware give
the FIRST mappings piece top sprite priority (SonLVL iterates pieces in reverse);
`renderFrameToIndices` composites in array order (last wins), so a monitor's opaque
4×4 shell (declared after its icon) painted over the icon and every subtype rendered
identically. `renderObjectFrame` now reverses piece order — icons/overlays composite
correctly. This corrects all object previews, not just composites.

### B5 deviation notes
- **Swinging Platform palette approximation.** SonLVL palettes the chain link on line 0
  and the anchor/platform on line 2, and swaps the platform for a wrecking ball when
  `subtype & 0x10`. The composer applies ONE palette line per composite (indices →
  single CRAM line), so all pieces render on the platform's line and the wrecking-ball
  variant is not modelled. Geometry is exact; documented follow-up if per-piece palette
  is wanted (would require the composer to emit RGBA per piece).
- **LevelArt / offset-art / dual-art objects stay unlinked** (see s1-object-art.ts
  curation) — they need pipelines the .nem+mappings path doesn't provide.
- **Piece-order reversal** is a general fix to `renderObjectFrame` (affects the B1
  single-frame path too); it is the correct S1 sprite priority and only changes output
  where a frame's pieces overlap.
